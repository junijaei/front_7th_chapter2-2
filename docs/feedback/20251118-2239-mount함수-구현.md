**작성일**: 2025-11-18 22:39
**대상 파일**: `packages/react/src/core/reconciler.ts:50-105`
**학습 목표**: VNode → Instance → DOM 변환 흐름 완전히 이해하기

## 현재 코드

```typescript
const mount = (parentDom: HTMLElement, node: VNode) => {
  // Case 1: TEXT_ELEMENT 처리
  if (node.type === TEXT_ELEMENT) {
    const dom = document.createTextNode(node.props.nodeValue);
    return {
      kind: "text",
      dom,
      children: [null],
      key: null,
      node,
      path: "",
    } as Instance;
  }

  const { key } = node;

  // Case 2: 문자열 타입 (DOM 요소) 처리
  if (typeof node.type === "string") {
    const dom = document.createElement(node.type);

    const { children, ...props } = node.props;

    setDomProps(dom, props);

    const instance: Instance = {
      kind: "host",
      dom,
      children: [],
      key,
      node,
      path: "",
    };

    if (children) {
      instance.children = children.map((child) => {
        return reconcile(dom, null, child, "");
      });
    }

    insertInstance(parentDom, instance);
    return instance;
  }

  // Case 3: 함수 타입 (컴포넌트) 처리
  if (typeof node.type === "function") {
    const newVNode = node.type(node.props);

    const childInstance = reconcile(parentDom, null, newVNode, "");
    return {
      kind: "component",
      dom: null,
      children: [childInstance],
      key,
      node,
      path: "",
    };
  }

  throw new Error(`알 수 없는 노드 타입: ${String(node.type)}`);
};
```

## 피드백

### ✅ 잘한 점

#### 1. 3가지 타입을 모두 처리했습니다!

VNode의 핵심 타입을 완벽하게 구분했어요:
- **TEXT_ELEMENT**: 텍스트 노드
- **문자열**: DOM 요소 (div, p, button 등)
- **함수**: 컴포넌트

이건 React의 핵심 개념을 이해했다는 증거입니다!

#### 2. DOM 요소 처리 로직이 정확합니다

```typescript
const dom = document.createElement(node.type);
const { children, ...props } = node.props;  // children 분리!
setDomProps(dom, props);
```

- children을 props에서 분리한 것: 👍
- `setDomProps`로 속성 적용: 👍
- 실제 DOM 생성: 👍

#### 3. 재귀 호출을 올바르게 사용했습니다

```typescript
instance.children = children.map((child) => {
  return reconcile(dom, null, child, "");
});
```

자식들도 Instance로 만들기 위해 `reconcile`을 재귀 호출했어요. 이게 핵심입니다!

#### 4. 컴포넌트의 특성을 이해했습니다

```typescript
if (typeof node.type === "function") {
  const newVNode = node.type(node.props);  // 함수 실행
  const childInstance = reconcile(parentDom, null, newVNode, "");
  return {
    kind: "component",
    dom: null,  // 컴포넌트는 DOM이 없다!
    // ...
  };
}
```

컴포넌트는:
- 함수를 **실행**해서 VNode를 얻고
- 그 VNode를 다시 **reconcile**로 처리하고
- 자체 DOM은 **없다** (`dom: null`)

완벽하게 이해하셨네요!

#### 5. 에러 처리를 추가했습니다

```typescript
throw new Error(`알 수 없는 노드 타입: ${String(node.type)}`);
```

예상치 못한 타입에 대한 에러 처리는 디버깅에 큰 도움이 됩니다.

### 🤔 개선할 점

#### 1. **path 파라미터를 받지 않고 있습니다** ⚠️ 중요!

**현재 문제:**
```typescript
const mount = (parentDom: HTMLElement, node: VNode) => {
  // path 파라미터가 없어요!
}
```

**왜 문제인가요?**

path는 **컴포넌트의 고유 경로**입니다. 이게 왜 중요할까요?

```typescript
function App() {
  const [count, setCount] = useState(0);  // 이 state는 어디에 저장될까요?
  return <div>{count}</div>;
}
```

**useState가 state를 저장하는 위치:**
```typescript
// hooks/context.ts에서
state: Map<string, State[]>
         ↑
         여기 key가 바로 path예요!
```

path가 없으면:
- 훅의 state를 저장할 수 없어요
- 같은 컴포넌트를 여러 번 사용할 때 state가 섞여요
- 업데이트 시 어느 컴포넌트인지 식별 불가

**해결 방법:**
```typescript
const mount = (
  parentDom: HTMLElement,
  node: VNode,
  path: string,  // ← 파라미터 추가!
) => {
  // ...
  if (node.type === TEXT_ELEMENT) {
    return {
      // ...
      path,  // ← 빈 문자열 대신 파라미터 사용!
    };
  }
  // ...
}
```

그리고 reconcile 호출 시에도:
```typescript
// ❌ 현재
return mount(parentDom, node);

// ✅ 개선
return mount(parentDom, node, path);
```

#### 2. **자식의 path를 생성하지 않았습니다** ⚠️ 중요!

**현재 코드:**
```typescript
if (children) {
  instance.children = children.map((child) => {
    return reconcile(dom, null, child, "");  // ← 빈 문자열!
  });
}
```

**문제:**
모든 자식의 path가 `""`로 같아요! 이러면:

```jsx
<div>
  <Counter />  {/* path: "" */}
  <Counter />  {/* path: "" */}
</div>
```

두 Counter가 같은 path를 가져서 state가 섞여버립니다!

**해결 방법:**

`createChildPath`를 사용해서 각 자식마다 고유한 path 만들기:

```typescript
if (children) {
  instance.children = children.map((child, index) => {
    // 각 자식의 고유 경로 생성
    const childPath = createChildPath(
      path,           // 부모 경로
      child.key,      // 자식의 key (있으면)
      index,          // 배열 인덱스
      child.type,     // 노드 타입 (선택)
      children,       // 형제들 (선택)
    );
    return reconcile(dom, null, child, childPath);
  });
}
```

**왜 createChildPath가 필요한가요?**

```
부모 path: "App"
자식들:
  - "App.0" (첫 번째 자식)
  - "App.1" (두 번째 자식)
  - "App.button" (key="button"인 자식)

이렇게 계층 구조로 경로를 만들어요!
```

#### 3. **TEXT_ELEMENT의 children이 `[null]`입니다**

**현재:**
```typescript
if (node.type === TEXT_ELEMENT) {
  return {
    // ...
    children: [null],  // ← null을 담은 배열?
  };
}
```

**개선:**
```typescript
children: [],  // 텍스트는 자식이 없어요!
```

텍스트 노드는 자식을 가질 수 없으므로 빈 배열이 더 명확합니다.

#### 4. **key를 TEXT_ELEMENT에서만 null로 고정했습니다**

**TEXT_ELEMENT 처리:**
```typescript
if (node.type === TEXT_ELEMENT) {
  return {
    // ...
    key: null,  // ← 고정값
  };
}
```

**개선:**
```typescript
key: node.key,  // VNode의 key를 그대로 사용
```

비록 텍스트 노드가 보통 key를 안 가지지만, VNode에 있다면 보존하는 게 일관성 있어요.

### 💡 학습 포인트

#### 1. mount 함수의 핵심 책임

```
mount = VNode를 받아서 → Instance 생성 → DOM 생성 → 부모에 삽입
```

각 타입별 처리:

| VNode 타입 | DOM 생성 | 자식 처리 | 특이사항 |
|-----------|---------|---------|---------|
| TEXT_ELEMENT | createTextNode | 없음 | 가장 단순 |
| 문자열 (div 등) | createElement | 재귀 reconcile | setDomProps 필요 |
| 함수 (컴포넌트) | 없음 (null) | 함수 실행 후 reconcile | DOM 없이 Instance만 |

#### 2. path의 중요성

```typescript
// path 구조 예시
"App"                    // 루트 컴포넌트
"App.0"                  // App의 첫 번째 자식
"App.0.Counter"          // 컴포넌트 이름이 있으면 사용
"App.1.button"           // key가 있으면 key 사용
```

**path가 사용되는 곳:**
1. **Hook state 저장**: `hooks.state.get(path)`
2. **Hook cursor 관리**: `hooks.cursor.get(path)`
3. **컴포넌트 식별**: 어느 컴포넌트를 업데이트할지 결정

#### 3. 재귀 호출의 아름다움

```typescript
// DOM 요소의 자식 처리
children.map((child) => reconcile(dom, null, child, childPath))

// 컴포넌트의 결과 처리
reconcile(parentDom, null, newVNode, path)
```

mount → reconcile → mount → reconcile → ...

이 재귀가 전체 트리를 Instance로 변환합니다!

#### 4. Instance의 3가지 kind

```typescript
kind: "text"       // 텍스트 노드 (dom: Text)
kind: "host"       // DOM 요소 (dom: HTMLElement)
kind: "component"  // 컴포넌트 (dom: null)
```

**왜 구분할까요?**

update 함수에서 각각 다르게 처리해야 하거든요:
- text: nodeValue만 업데이트
- host: props 업데이트 + 자식 재조정
- component: 함수 재실행 + 자식 재조정

## 개선된 코드 예시

```typescript
const mount = (
  parentDom: HTMLElement,
  node: VNode,
  path: string,  // ← 추가!
): Instance => {

  // Case 1: TEXT_ELEMENT
  if (node.type === TEXT_ELEMENT) {
    const dom = document.createTextNode(node.props.nodeValue);
    return {
      kind: "text",
      dom,
      node,
      children: [],      // ← 빈 배열
      key: node.key,     // ← VNode의 key
      path,              // ← 파라미터 사용
    };
  }

  const { key } = node;

  // Case 2: DOM 요소
  if (typeof node.type === "string") {
    const dom = document.createElement(node.type);
    const { children, ...props } = node.props;

    setDomProps(dom, props);

    const instance: Instance = {
      kind: "host",
      dom,
      node,
      children: [],
      key,
      path,              // ← 파라미터 사용
    };

    if (children) {
      instance.children = children.map((child, index) => {
        const childPath = createChildPath(path, child.key, index);  // ← 경로 생성!
        return reconcile(dom, null, child, childPath);
      });
    }

    insertInstance(parentDom, instance);
    return instance;
  }

  // Case 3: 컴포넌트
  if (typeof node.type === "function") {
    const newVNode = node.type(node.props);
    const childInstance = reconcile(parentDom, null, newVNode, path);

    return {
      kind: "component",
      dom: null,
      node,
      children: [childInstance],
      key,
      path,              // ← 파라미터 사용
    };
  }

  throw new Error(`알 수 없는 노드 타입: ${String(node.type)}`);
};
```

**reconcile에서 호출할 때도:**

### createChildPath 구현 확인

현재 `createChildPath`가 빈 문자열을 반환하고 있다면, 이것도 구현해야 해요:

```typescript
// elements.ts
export const createChildPath = (
  parentPath: string,
  key: string | null,
  index: number,
  nodeType?: string | symbol | React.ComponentType,
  siblings?: VNode[],
): string => {
  // 부모 경로가 비어있으면 (루트)
  const prefix = parentPath ? `${parentPath}.` : "";

  // key가 있으면 key 사용
  if (key) return `${prefix}${key}`;

  // 컴포넌트 이름이 있으면 사용
  if (typeof nodeType === "function" && nodeType.name) {
    return `${prefix}${nodeType.name}`;
  }

  // 없으면 인덱스 사용
  return `${prefix}${index}`;
};
```

## 마무리

### 정말 잘하신 점

1. mount 함수의 **전체 구조**를 올바르게 잡았어요
2. **3가지 타입**을 모두 구분해서 처리했어요

### 개선할 핵심

1. **path 파라미터** 추가 (훅 시스템에 필수!)
2. **createChildPath**로 자식 경로 생성 (state 격리에 필수!)

이 두 가지만 수정하면 mount 함수는 완벽합니다!
