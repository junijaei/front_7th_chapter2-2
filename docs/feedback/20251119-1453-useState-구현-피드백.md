**대상 파일**: `packages/react/src/core/hooks.ts:19-44`
**학습 목표**: React Hooks의 상태 관리 메커니즘과 클로저 개념 이해

---

## 현재 코드

```typescript
export const useState = <T>(initialValue: T | (() => T)): [T, (nextValue: T | ((prev: T) => T)) => void] => {
  const path = context.hooks.currentPath;
  const hooks = context.hooks.currentHooks;
  const cursor = context.hooks.currentCursor;

  if (hooks[cursor] === undefined) {
    hooks[cursor] = typeof initialValue === "function" ? initialValue() : initialValue;
  }

  const setState = (nextValue: T | ((prev: T) => T)) => {
    const next = typeof nextValue === "function" ? nextValue() : nextValue;
    if (!shallowEquals(hooks[cursor], next)) {
      hooks[cursor] = next;
      enqueueRender();
    }
  };

  context.hooks.cursor.set(path, cursor + 1);
  return [hooks[cursor], setState];
};
```

## 피드백

### ✅ 잘한 점

#### 1. 전체 구조와 흐름을 정확히 이해했습니다

```typescript
const path = context.hooks.currentPath;
const hooks = context.hooks.currentHooks;
const cursor = context.hooks.currentCursor;
```

path, hooks, cursor를 모두 가져오는 것으로 시작한 것이 완벽합니다! 이 세 가지가 useState의 핵심 재료라는 것을 정확히 파악하셨어요.

#### 2. 첫 렌더링 확인 로직이 정확합니다

```typescript
if (hooks[cursor] === undefined) {
  hooks[cursor] = typeof initialValue === "function" ? initialValue() : initialValue;
}
```

`undefined` 체크로 첫 렌더링을 구분하고, 삼항 연산자로 함수/값을 처리한 것이 훌륭합니다. 이것이 React에서 "lazy initial state"를 구현하는 방식입니다!

#### 3. 커서 증가를 올바른 위치에 배치했습니다

```typescript
context.hooks.cursor.set(path, cursor + 1);
return [hooks[cursor], setState];
```

반환 직전에 커서를 증가시켜서 다음 훅 호출을 준비한 것이 정확합니다. 이것이 "Hooks are called in the same order" 규칙을 지키는 핵심이에요!

#### 4. Object.is 대신 shallowEquals를 고민한 흔적이 보입니다

비교 함수를 사용하려고 한 시도가 좋았어요. 값 비교의 중요성을 이해하고 계시네요!

#### 5. enqueueRender 호출 위치가 적절합니다

값이 변경되었을 때만 리렌더링을 예약하는 구조를 만들었어요. 불필요한 렌더링을 방지하는 최적화를 고려한 것이 훌륭합니다!

### 🤔 개선할 점

#### 1. **클로저 캡처 누락** ⚠️ 중요!

**현재 문제:**
```typescript
const setState = (nextValue: T | ((prev: T) => T)) => {
  const next = typeof nextValue === "function" ? nextValue() : nextValue;
  if (!shallowEquals(hooks[cursor], next)) {  // ❌ cursor 사용
    hooks[cursor] = next;  // ❌ cursor 사용
    enqueueRender();
  }
};
```

**왜 문제인가요?**

`setState`는 나중에 호출되는 함수인데, 그때는 `cursor` 값이 이미 바뀌어 있을 수 있습니다.

예를 들어 이런 컴포넌트가 있다면:
```typescript
function Counter() {
  const [count, setCount] = useState(0);     // cursor = 0
  const [name, setName] = useState("홍길동"); // cursor = 1

  // 여기서 버튼 클릭 → setCount 호출
  // 하지만 이미 useState 실행이 끝났고 cursor는 2가 됨!
  return <button onClick={() => setCount(count + 1)}>증가</button>;
}
```

다음 렌더링 시:
```
1. render() 호출 → cursor Map 초기화
2. useState(0) 호출 → cursor = 0
3. useState("홍길동") 호출 → cursor = 1
4. 렌더링 완료 → cursor는 마지막으로 2

[사용자가 버튼 클릭]
5. setCount 내부에서 hooks[cursor] 접근
   → cursor는 현재 몇일까요? 불확실합니다!
   → 이전 렌더링의 마지막 값일 수도, 다른 값일 수도 있음
```

**해결 방법:**

```typescript
// ❌ 현재: cursor를 직접 참조
const setState = (nextValue: T | ((prev: T) => T)) => {
  const next = typeof nextValue === "function" ? nextValue() : nextValue;
  if (!shallowEquals(hooks[cursor], next)) {
    hooks[cursor] = next;
    // ...
  }
};

// ✅ 개선: cursor를 클로저로 캡처
const currentCursor = cursor; // 현재 시점의 cursor 값을 상수로 저장!

const setState = (nextValue: T | ((prev: T) => T)) => {
  const next = typeof nextValue === "function" ? nextValue() : nextValue;
  if (!shallowEquals(hooks[currentCursor], next)) {  // 캡처된 값 사용
    hooks[currentCursor] = next;
    // ...
  }
};
```

**클로저란?**
- 함수가 생성될 때의 환경(변수)을 "기억"하는 것
- `currentCursor`는 useState 실행 시점의 값을 영구히 기억
- 나중에 setState가 호출되어도 올바른 인덱스를 사용

#### 2. **함수형 업데이트의 인자 전달 누락** ⚠️ 필수

**현재 문제:**
```typescript
const next = typeof nextValue === "function" ? nextValue() : nextValue;
//                                              ^^^^^^^^^^^^
//                                              인자 없이 호출!
```

**왜 문제인가요?**

사용자가 이렇게 호출할 때:
```typescript
setCount(prev => prev + 1);
```

`prev`에 현재 값이 들어가야 하는데, 아무것도 전달하지 않았어요.

**실제 동작:**
```typescript
const callback = (prev) => prev + 1;
const next = callback();  // prev는 undefined!
// next = undefined + 1 = NaN
```

**해결 방법:**

```typescript
// ❌ 현재: 인자 없이 호출
const next = typeof nextValue === "function"
  ? nextValue()  // prev가 undefined
  : nextValue;

// ✅ 개선: 현재 상태를 인자로 전달
const next = typeof nextValue === "function"
  ? (nextValue as (prev: T) => T)(hooks[currentCursor])  // 현재 값 전달!
  : nextValue;
```

**왜 타입 캐스팅이 필요한가요?**
- TypeScript는 `nextValue`가 함수인지 값인지 정확히 모름
- `as (prev: T) => T`로 "이건 함수야"라고 알려줘야 함

#### 3. **비교 함수 선택 오류** 💡 권장

**현재 문제:**
```typescript
if (!shallowEquals(hooks[cursor], next)) {
```

**왜 문제인가요?**

주석에는 `Object.is`를 사용하라고 되어 있는데 `shallowEquals`를 사용했어요.

두 함수의 차이:
```typescript
// Object.is - 값 자체를 비교
Object.is(1, 1)           // true
Object.is("a", "a")       // true
Object.is({}, {})         // false (다른 객체)
Object.is(NaN, NaN)       // true (=== 와 다른 점)

// shallowEquals - 배열/객체의 얕은 비교
shallowEquals([1, 2], [1, 2])     // 배열 내용 비교
shallowEquals({a: 1}, {a: 1})     // 객체 속성 비교
```

**useState는 모든 타입을 다룹니다:**
- 원시값: 숫자, 문자열, boolean
- 객체: 참조 비교
- 배열: 참조 비교

React는 `Object.is`를 사용합니다. 이유는:
1. 빠름 (얕은 비교보다 훨씬 빠름)
2. 객체/배열은 참조가 바뀌어야 리렌더링
3. `setState({...prev})` 같은 패턴 강제

**해결 방법:**

```typescript
// ❌ 현재: shallowEquals
if (!shallowEquals(hooks[currentCursor], next)) {
  // ...
}

// ✅ 개선: Object.is
if (!Object.is(hooks[currentCursor], next)) {
  // ...
}
```

#### 4. **타입 안정성 개선** 📝 참고

**현재 코드:**
```typescript
hooks[cursor] = typeof initialValue === "function" ? initialValue() : initialValue;
```

TypeScript가 `initialValue`의 타입을 정확히 모를 수 있어요.

**개선 코드:**
```typescript
hooks[cursor] = typeof initialValue === "function"
  ? (initialValue as () => T)()  // 명시적 타입 캐스팅
  : initialValue;
```

이렇게 하면 TypeScript가 "아, 이건 T를 반환하는 함수구나"라고 정확히 이해합니다.

### 💡 학습 포인트

#### 1. 클로저 (Closure)

클로저는 함수가 생성될 때의 환경을 기억하는 JavaScript의 핵심 개념입니다.

**예시:**
```typescript
function createCounter() {
  let count = 0;  // 이 변수는 함수 실행 후 사라질까요?

  return function increment() {
    count++;  // 아니요! 클로저로 기억됩니다!
    return count;
  };
}

const counter1 = createCounter();
counter1();  // 1
counter1();  // 2

const counter2 = createCounter();
counter2();  // 1 (독립적인 클로저)
```

**useState에서의 클로저:**
```typescript
export const useState = <T>(initialValue: T) => {
  const cursor = context.hooks.currentCursor;  // 0
  const currentCursor = cursor;  // 0을 영구히 기억!

  const setState = (next: T) => {
    hooks[currentCursor] = next;  // 항상 0번 인덱스!
  };

  return [hooks[cursor], setState];
};
```

다음 렌더링에서:
```typescript
const cursor = context.hooks.currentCursor;  // 다시 0
const currentCursor = cursor;  // 새로운 0을 기억

// 이전 setState는 이전의 0을 기억
// 새 setState는 새로운 0을 기억
// 각자 독립적!
```

#### 2. 함수형 업데이트의 필요성

**왜 함수형 업데이트가 필요할까요?**

```typescript
// 시나리오 1: 값으로 업데이트
const [count, setCount] = useState(0);

function handleClick() {
  setCount(count + 1);  // count = 0
  setCount(count + 1);  // count = 0 (아직 리렌더링 안됨!)
  // 결과: 1 (2가 아님!)
}

// 시나리오 2: 함수로 업데이트
function handleClick() {
  setCount(prev => prev + 1);  // prev = 0, 결과 = 1
  setCount(prev => prev + 1);  // prev = 1, 결과 = 2
  // 결과: 2
}
```

함수형 업데이트는 **최신 상태**를 보장합니다!

**구현 비교:**
```typescript
// ❌ 잘못된 구현
const next = typeof nextValue === "function"
  ? nextValue()  // 현재 상태를 모름!
  : nextValue;

// ✅ 올바른 구현
const next = typeof nextValue === "function"
  ? nextValue(hooks[currentCursor])  // 현재 상태 전달!
  : nextValue;
```

#### 3. React의 배칭 (Batching)

여러 setState를 연속으로 호출해도 리렌더링은 한 번만 일어납니다.

```typescript
function handleClick() {
  setCount(1);
  setName("홍길동");
  setAge(25);
  // 렌더링은 한 번만!
}
```

**어떻게?**

`enqueueRender`가 마이크로태스크 큐를 사용합니다:

```typescript
// withEnqueue 구현 (utils/enqueue.ts)
export const withEnqueue = (fn) => {
  let pending = false;

  return () => {
    if (pending) return;  // 이미 예약됨

    pending = true;
    queueMicrotask(() => {
      pending = false;
      fn();  // 실제 렌더링
    });
  };
};
```

**실행 순서:**
```
1. setCount(1) → hooks[0] = 1, enqueueRender() 호출
   → pending = true, queueMicrotask(render)

2. setName("홍길동") → hooks[1] = "홍길동", enqueueRender() 호출
   → pending이 true이므로 return (중복 방지!)

3. setAge(25) → hooks[2] = 25, enqueueRender() 호출
   → pending이 true이므로 return

4. 현재 실행 컨텍스트 종료

5. 마이크로태스크 실행 → render() 한 번만 호출!
```

#### 4. Hook 커서의 리셋 타이밍

**의문**: 왜 cursor를 증가시키는데, 다음 렌더링에서는 0부터 시작할까요?

**답**: `render` 함수에서 cursor Map을 초기화합니다!

```typescript
// core/render.ts
export const render = (): void => {
  context.hooks.visited.clear();
  context.hooks.cursor.clear();  // 🔥 여기서 모든 커서 리셋!

  const newInstance = reconcile(/* ... */);
  // ...
};
```

**전체 사이클:**
```
[렌더링 시작]
render() → cursor Map 초기화

[Counter 컴포넌트]
useState(0) → cursor = 0 → cursor.set("0.c0", 1)
useState("홍길동") → cursor = 1 → cursor.set("0.c0", 2)

[렌더링 끝]

[setCount 호출]
setState(1) → enqueueRender()

[다음 렌더링 시작]
render() → cursor Map 초기화 (다시 0부터!)

[Counter 컴포넌트]
useState(0) → cursor = 0 (리셋되었으므로)
useState("홍길동") → cursor = 1
```

## 개선된 코드 예시

```typescript
export const useState = <T>(initialValue: T | (() => T)): [T, (nextValue: T | ((prev: T) => T)) => void] => {
  // 1. 현재 컴포넌트의 훅 커서와 상태 배열을 가져옵니다.
  const path = context.hooks.currentPath;
  const hooks = context.hooks.currentHooks;
  const cursor = context.hooks.currentCursor;

  // 2. 첫 렌더링이라면 초기값으로 상태를 설정합니다.
  if (hooks[cursor] === undefined) {
    hooks[cursor] = typeof initialValue === "function"
      ? (initialValue as () => T)()  // 함수 실행
      : initialValue;
  }

  // 3. 상태 변경 함수(setter)를 생성합니다.
  const currentCursor = cursor; // 🔥 클로저로 커서 캡처!

  const setState = (nextValue: T | ((prev: T) => T)) => {
    // 함수형 업데이트 처리: 이전 값을 인자로 전달
    const next = typeof nextValue === "function"
      ? (nextValue as (prev: T) => T)(hooks[currentCursor])  // 🔥 현재 값 전달!
      : nextValue;

    // 새 값이 이전 값과 같으면(Object.is) 재렌더링을 건너뜁니다.
    if (!Object.is(hooks[currentCursor], next)) {  // 🔥 Object.is + currentCursor
      // 값이 다르면 상태를 업데이트하고 재렌더링을 예약합니다.
      hooks[currentCursor] = next;
      enqueueRender();
    }
  };

  // 4. 훅 커서를 증가시키고 [상태, setter]를 반환합니다.
  context.hooks.cursor.set(path, cursor + 1);
  return [hooks[cursor], setState];
};
```

**변경 사항 요약:**
1. ✅ `currentCursor` 변수 추가 (클로저 캡처)
2. ✅ 함수형 업데이트 시 `hooks[currentCursor]` 전달
3. ✅ `shallowEquals` → `Object.is` 변경
4. ✅ 타입 캐스팅 추가 (선택사항)

## 추가 질문과 답변

### Q. cursor 값을 클로저로 캡처하는데, 반환할 때는 왜 currentCursor를 안 쓰고 cursor를 쓰는 거야??

**정말 좋은 질문입니다!** 이 부분이 헷갈릴 수 있어요.

#### 핵심: 지금 실행 vs 나중 실행

```typescript
const cursor = 0;
const currentCursor = cursor; // 클로저 캡처

const setState = (nextValue) => {
  hooks[currentCursor] = next;  // 🕐 나중에 실행
};

return [hooks[cursor], setState];  // 🕐 지금 바로 실행!
```

#### 왜 return에서는 cursor를 써도 되나?

**`return [hooks[cursor], setState]`는 지금 당장 실행되는 코드입니다!**

타임라인으로 보면:

```javascript
// T = 0ms: useState(0) 실행
const cursor = 0;  // cursor는 정확히 0
const currentCursor = cursor;

const setState = (next) => {
  // 이 코드는 아직 실행 안됨! 함수 정의만!
};

// T = 0ms: 바로 여기서 hooks[cursor] 읽음
return [hooks[cursor], setState];
       // ↑ hooks[0]을 "지금" 읽어서 반환
       // cursor는 아직 0이므로 정확함!

// T = 0ms: useState(0) 끝
context.hooks.cursor.set(path, 1);

// T = 1000ms: 나중에 사용자가 버튼 클릭
setState(1);
// 여기서 setState 내부 코드가 실행됨
// 만약 hooks[cursor]였다면? cursor는 이미 바뀜!
// currentCursor를 썼으니 안전!
```

#### 실제 비교

```typescript
// ❌ 만약 setState에서 cursor를 직접 쓴다면
const setState = (next) => {
  hooks[cursor] = next;  // cursor는 지금 몇? 불확실!
};
return [hooks[cursor], setState];  // 지금은 정확함

// ✅ currentCursor 캡처
const setState = (next) => {
  hooks[currentCursor] = next;  // 항상 0!
};
return [hooks[cursor], setState];  // 지금 0, 정확함
```

#### 핵심 원리

**return 문은 함수가 아닙니다!**
- `return` 뒤의 코드는 즉시 평가됨
- `hooks[cursor]`는 지금 이 순간 배열에서 값을 읽음
- 나중에 다시 읽는 게 아님

**setState는 함수입니다!**
- 함수 내부 코드는 호출될 때까지 실행 안됨
- 호출 시점에 `cursor` 값이 바뀌어 있을 수 있음

#### 만약 return에서도 currentCursor를 쓴다면?

```typescript
return [hooks[currentCursor], setState];
```

**동작합니다!** 하지만 불필요해요.

왜냐하면 이 시점에서:
```typescript
cursor === currentCursor  // true (같은 값)
```

둘 다 0이니까 `hooks[cursor]`든 `hooks[currentCursor]`든 같은 결과입니다.

#### 정리

| 위치 | 사용 변수 | 실행 시점 | 안전성 |
|------|----------|----------|--------|
| `return [hooks[cursor], ...]` | cursor | 지금 즉시 | ✅ 안전 |
| `setState = () => { hooks[cursor] }` | cursor | 나중에 호출 시 | ❌ 위험 |
| `setState = () => { hooks[currentCursor] }` | currentCursor | 나중에 호출 시 | ✅ 안전 |

**핵심**: return 문의 표현식은 **지금 바로 평가**되므로 cursor를 직접 써도 안전합니다!
