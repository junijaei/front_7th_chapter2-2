# useEffect 구현 피드백

**작성일**: 2025-11-20 19:46
**대상 파일**: `packages/react/src/core/hooks.ts:53-80`
**학습 목표**: useEffect의 비동기 실행, 클린업 함수 관리, 의존성 비교 패턴 이해

## 현재 코드

```typescript
export const useEffect = (effect: () => (() => void) | void, deps?: unknown[]): void => {
  const path = context.hooks.currentPath;
  const hooks = context.hooks.currentHooks;
  const cursor = context.hooks.currentCursor;
  const prevHooks = hooks[cursor] as EffectHook | undefined;
  const prevDeps = prevHooks?.deps;

  const shouldRun = prevDeps === undefined || deps === undefined || !shallowEquals(prevDeps, deps);

  hooks[cursor] = {
    kind: HookTypes.EFFECT,
    deps,
    effect,
    cleanup: prevHooks?.cleanup,
  } as EffectHook;

  if (shouldRun) {
    if (prevHooks?.cleanup) prevHooks?.cleanup();
    withEnqueue(effect);
  }
  context.hooks.cursor.set(path, cursor + 1);
};
```

## 피드백

### ✅ 잘한 점

#### 1. 커서 기반의 훅 상태 관리를 정확히 이해했습니다

```typescript
const cursor = context.hooks.currentCursor;
// ...
context.hooks.cursor.set(path, cursor + 1);
```

훅 호출 순서를 추적하기 위해 커서를 사용하고, 훅 실행 후 커서를 증가시키는 패턴을 올바르게 적용했습니다. 이것이 React의 "Rules of Hooks"가 동작하는 핵심 원리입니다!

#### 2. 의존성 비교 로직이 잘 구현되었습니다

```typescript
const shouldRun = prevDeps === undefined || deps === undefined || !shallowEquals(prevDeps, deps);
```

세 가지 케이스를 모두 고려했습니다:
- 첫 렌더링 (`prevDeps === undefined`)
- deps가 생략된 경우 (`deps === undefined`) → 매번 실행
- 의존성 값이 변경된 경우

#### 3. EffectHook 타입을 올바르게 활용했습니다

```typescript
hooks[cursor] = {
  kind: HookTypes.EFFECT,
  deps,
  effect,
  cleanup: prevHooks?.cleanup,
} as EffectHook;
```

타입 정의에 맞춰 `kind`, `deps`, `effect`, `cleanup` 필드를 모두 포함했습니다.

#### 4. 이전 cleanup 함수를 조건부로 실행했습니다

```typescript
if (prevHooks?.cleanup) prevHooks?.cleanup();
```

이전 effect의 cleanup 함수가 존재할 때만 실행하도록 처리한 것은 좋습니다.

#### 5. withEnqueue를 사용해 비동기 실행을 시도했습니다

```typescript
withEnqueue(effect);
```

effect가 동기적으로 실행되면 안 된다는 것을 이해하고 있습니다. 하지만 `withEnqueue`의 동작 방식에 대한 추가 이해가 필요합니다.

### 🤔 개선할 점

#### 1. **cleanup 함수가 저장되지 않음** ⚠️ 중요!

**현재 문제:**
```typescript
if (shouldRun) {
  if (prevHooks?.cleanup) prevHooks?.cleanup();
  withEnqueue(effect);  // effect 실행만 하고 반환값(cleanup)은 저장 안 함!
}
```

**왜 문제인가요?**

effect 함수는 cleanup 함수를 반환할 수 있습니다:
```typescript
useEffect(() => {
  const timer = setInterval(...);
  return () => clearInterval(timer);  // 이 cleanup이 저장되어야 함
}, []);
```

현재 코드에서 `withEnqueue(effect)`는 effect를 실행하지만, **반환된 cleanup 함수를 받아서 저장하지 않습니다**. 따라서 다음 렌더링이나 언마운트 시 cleanup이 호출되지 않습니다.

**테스트 실패 예상:**
```typescript
it("useEffect 클린업은 재실행과 언마운트 시 호출된다", async () => {
  // cleanupCount가 증가하지 않음!
  expect(cleanupCount).toBe(1);  // 실패: 실제로는 0
});
```

**해결 방법:**

React의 실제 동작 방식을 따라야 합니다. effect를 즉시 실행하지 말고 **큐에 등록**해두었다가, 렌더링이 끝난 후 `flushEffects`에서 실행하면서 cleanup을 저장해야 합니다.

```typescript
// ❌ 현재: withEnqueue로 즉시 스케줄링 (cleanup 저장 불가)
withEnqueue(effect);

// ✅ 개선: 큐에 등록하고 나중에 flushEffects에서 실행
if (shouldRun) {
  if (prevHooks?.cleanup) prevHooks?.cleanup();
  context.effects.queue.push({ path, cursor });  // 큐에 등록만
}
```

그리고 `flushEffects` 함수에서:
```typescript
const flushEffects = () => {
  while (context.effects.queue.length > 0) {
    const { path, cursor } = context.effects.queue.shift()!;
    const hooks = context.hooks.state.get(path);
    const hook = hooks?.[cursor] as EffectHook;

    if (hook) {
      const cleanup = hook.effect();  // effect 실행
      hook.cleanup = cleanup ?? null;  // cleanup 저장!
    }
  }
};
```

#### 2. **withEnqueue의 동작 방식 오해** ⚠️ 중요!

**현재 문제:**
```typescript
withEnqueue(effect);  // effect마다 withEnqueue 호출
```

**왜 문제인가요?**

`withEnqueue`는 함수를 **한 번만 스케줄링**하는 고차 함수입니다:

```typescript
export const withEnqueue = (fn: AnyFunction) => {
  let scheduled = false;
  return () => {
    if (scheduled) return;  // 이미 예약되었으면 스킵
    scheduled = true;
    enqueue(() => {
      scheduled = false;
      fn();
    });
  };
};
```

`withEnqueue(effect)`를 호출하면 **매번 새로운 래퍼 함수를 생성**합니다. 이 래퍼 함수는 한 번도 호출되지 않은 상태이므로 실제로 effect가 실행되지 않습니다!

```typescript
const enqueuedFn = withEnqueue(effect);  // 래퍼 생성만 함
// enqueuedFn()을 호출해야 실제로 스케줄링됨!
```

**해결 방법:**

`withEnqueue`는 `render`처럼 **전역적으로 한 번만 스케줄링해야 하는 함수**에 사용합니다. effect 실행은 `context.effects.queue`를 활용하세요.

```typescript
// ❌ 현재
withEnqueue(effect);

// ✅ 개선 옵션 1: 단순히 enqueue 사용
if (shouldRun) {
  if (prevHooks?.cleanup) prevHooks?.cleanup();
  enqueue(() => {
    const cleanup = effect();
    const hook = hooks[cursor] as EffectHook;
    hook.cleanup = cleanup ?? null;
  });
}

// ✅ 개선 옵션 2 (권장): 큐에 등록하고 flushEffects에서 일괄 처리
if (shouldRun) {
  if (prevHooks?.cleanup) prevHooks?.cleanup();
  context.effects.queue.push({ path, cursor });
}
```

#### 3. **flushEffects 호출이 없음** ⚠️ 필수

**현재 문제:**

`render.ts`를 보면 `flushEffects` 호출이 없습니다:

```typescript
export const render = (): void => {
  context.hooks.visited.clear();
  context.hooks.cursor.clear();
  const newInstance = reconcile(...);
  context.root.instance = newInstance;
  cleanupUnusedHooks();
  // flushEffects()가 없음!
};
```

**왜 문제인가요?**

`context.effects.queue`에 등록된 effect들을 실행하는 로직이 필요합니다. React는 DOM 업데이트가 완료된 후 비동기적으로 effect를 실행합니다.

**해결 방법:**

`render.ts`에 flushEffects를 추가하세요:

```typescript
// render.ts
const flushEffects = () => {
  while (context.effects.queue.length > 0) {
    const { path, cursor } = context.effects.queue.shift()!;
    const hooks = context.hooks.state.get(path);
    const hook = hooks?.[cursor] as EffectHook;

    if (hook) {
      const cleanup = hook.effect();
      hook.cleanup = cleanup ?? null;
    }
  }
};

export const render = (): void => {
  context.hooks.visited.clear();
  context.hooks.cursor.clear();
  const newInstance = reconcile(...);
  context.root.instance = newInstance;
  cleanupUnusedHooks();

  // effect 실행을 마이크로태스크로 스케줄링
  enqueue(flushEffects);
};
```

#### 4. **cleanup 실행 시점이 동기적** 💡 권장

**현재 문제:**
```typescript
if (shouldRun) {
  if (prevHooks?.cleanup) prevHooks?.cleanup();  // 동기적으로 실행
  withEnqueue(effect);
}
```

**왜 문제인가요?**

React의 실제 동작에서는 cleanup도 비동기적으로 실행됩니다:

1. 렌더링 완료 (DOM 업데이트)
2. 마이크로태스크에서 이전 effect들의 cleanup 실행
3. 새 effect들 실행

현재 구현은 렌더링 중에 cleanup을 동기적으로 실행하고 있어서, 복잡한 케이스에서 예상치 못한 동작이 발생할 수 있습니다.

**해결 방법:**

cleanup도 effect 실행 시점에 함께 처리하세요:

```typescript
// useEffect에서
if (shouldRun) {
  context.effects.queue.push({ path, cursor });  // cleanup 관련 정보도 큐에 포함
}

// flushEffects에서
const flushEffects = () => {
  while (context.effects.queue.length > 0) {
    const { path, cursor } = context.effects.queue.shift()!;
    const hooks = context.hooks.state.get(path);
    const hook = hooks?.[cursor] as EffectHook;

    if (hook) {
      if (hook.cleanup) hook.cleanup();  // cleanup 먼저 실행
      const newCleanup = hook.effect();   // 새 effect 실행
      hook.cleanup = newCleanup ?? null;  // 새 cleanup 저장
    }
  }
};
```

#### 5. **deps 타입 처리** 📝 참고

**현재 문제:**
```typescript
hooks[cursor] = {
  // ...
  deps,  // undefined일 수 있음
} as EffectHook;
```

**EffectHook 타입 확인:**
```typescript
export interface EffectHook {
  kind: HookType["EFFECT"];
  deps: unknown[] | null;  // null을 기대함
  // ...
}
```

타입에서는 `deps`가 `unknown[] | null`인데, `undefined`를 저장하고 있습니다. 동작에는 문제없지만 타입 일관성을 위해 `null`로 변환하는 것이 좋습니다.

```typescript
// ✅ 개선
hooks[cursor] = {
  kind: HookTypes.EFFECT,
  deps: deps ?? null,  // undefined → null 변환
  effect,
  cleanup: prevHooks?.cleanup ?? null,
} as EffectHook;
```

### 💡 학습 포인트

#### 1. useEffect의 실행 흐름

```
┌─────────────────────────────────────────────────────────┐
│                    렌더링 사이클                          │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. setState 호출                                        │
│        ↓                                                │
│  2. enqueueRender() - 마이크로태스크에 render 등록        │
│        ↓                                                │
│  3. render() 실행                                        │
│        ├─ reconcile() - VNode → DOM                     │
│        └─ useEffect 호출됨                              │
│              └─ shouldRun이면 큐에 등록만                │
│        ↓                                                │
│  4. flushEffects() - 마이크로태스크에서 실행             │
│        ├─ 이전 cleanup 실행                             │
│        ├─ 새 effect 실행                                │
│        └─ 새 cleanup 저장                               │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

#### 2. cleanup 함수의 생명주기

| 시점 | cleanup 동작 |
|------|-------------|
| 첫 렌더링 | cleanup 없음, effect만 실행 |
| 의존성 변경 | 이전 cleanup 실행 → 새 effect 실행 → 새 cleanup 저장 |
| 같은 의존성 | 아무것도 안 함 |
| 컴포넌트 언마운트 | cleanup 실행 (cleanupUnusedHooks에서) |

#### 3. withEnqueue vs enqueue vs context.effects.queue

| 도구 | 용도 | 예시 |
|------|------|------|
| `withEnqueue` | 함수를 한 번만 스케줄링하는 래퍼 생성 | `enqueueRender = withEnqueue(render)` |
| `enqueue` | 콜백을 마이크로태스크에 등록 | `enqueue(() => doSomething())` |
| `context.effects.queue` | effect 실행 정보를 수집 | `queue.push({ path, cursor })` |

**중요**: `withEnqueue(fn)`은 **래퍼 함수를 반환**합니다. 반환된 함수를 **호출**해야 실제로 스케줄링됩니다.

```typescript
// withEnqueue의 올바른 사용
const scheduledFn = withEnqueue(fn);  // 래퍼 생성
scheduledFn();  // 이제야 스케줄링됨
scheduledFn();  // 무시됨 (이미 스케줄링됨)
```

## 추가 질문과 답변

### Q: 비동기 스케줄링을 어떻게 해야 하고, queue를 어떻게 사용해야 하나요?

#### 핵심 개념

useEffect는 **렌더링 중에는 실행하지 않고**, 렌더링이 **완료된 후** 비동기로 실행해야 합니다.

#### 전체 흐름

```
1. useEffect 호출 → 큐에 추가만 함 (실행 X)
2. 렌더링 완료
3. 마이크로태스크로 flushEffects 실행 → 큐의 모든 이펙트 실행
```

#### 구현 방법

##### 1단계: useEffect에서 큐에 추가

```typescript
// hooks.ts
export const useEffect = (effect: () => (() => void) | void, deps?: unknown[]): void => {
  const path = context.hooks.currentPath;
  const hooks = context.hooks.currentHooks;
  const cursor = context.hooks.currentCursor;
  const prevHook = hooks[cursor] as EffectHook | undefined;
  const prevDeps = prevHook?.deps;

  const shouldRun = prevDeps === undefined || deps === undefined || !shallowEquals(prevDeps, deps);

  // 훅 데이터 저장 (cleanup은 나중에 flushEffects에서 업데이트)
  hooks[cursor] = {
    kind: HookTypes.EFFECT,
    deps,
    effect,
    cleanup: prevHook?.cleanup,
  } as EffectHook;

  // 실행해야 하면 큐에 추가 (즉시 실행 X)
  if (shouldRun) {
    context.effects.queue.push({ path, cursor });
  }

  context.hooks.cursor.set(path, cursor + 1);
};
```

##### 2단계: flushEffects 구현

```typescript
// hooks.ts 또는 render.ts
export const flushEffects = () => {
  // 큐를 복사하고 비우기
  const queue = context.effects.queue;
  context.effects.queue = [];

  for (const { path, cursor } of queue) {
    const hooks = context.hooks.state.get(path);
    if (!hooks) continue;

    const hook = hooks[cursor] as EffectHook;

    // 1. 이전 cleanup 실행
    if (hook.cleanup) {
      hook.cleanup();
    }

    // 2. 새 이펙트 실행 & cleanup 저장
    const cleanup = hook.effect();
    hook.cleanup = cleanup || undefined;
  }
};
```

##### 3단계: render에서 flushEffects 스케줄링

```typescript
// render.ts
export const render = () => {
  // ... 렌더링 로직 (reconcile 등)

  // 렌더링 완료 후 이펙트 실행 (마이크로태스크)
  queueMicrotask(flushEffects);
  // 또는: Promise.resolve().then(flushEffects);
};
```

#### 왜 이렇게 해야 하나?

##### 1. 즉시 실행하면 안 되는 이유

```typescript
// ❌ 잘못된 방법
if (shouldRun) {
  if (prevHook?.cleanup) prevHook.cleanup();
  const cleanup = effect();  // 렌더링 중에 실행!
  hook.cleanup = cleanup;
}
```

문제점:
- DOM이 아직 업데이트되지 않았을 수 있음
- effect 안에서 DOM을 참조하면 이전 상태를 보게 됨
- 같은 렌더링의 여러 effect가 순서대로 실행되지 않을 수 있음

##### 2. 큐를 사용하는 이유

```typescript
// 여러 컴포넌트가 각각 useEffect를 호출
<App>           // useEffect → 큐에 추가
  <Header />    // useEffect → 큐에 추가
  <Content />   // useEffect → 큐에 추가
</App>

// 렌더링 완료 후 한꺼번에 실행
flushEffects(); // 큐의 모든 이펙트를 순서대로 실행
```

#### context.effects.queue 구조

```typescript
// context.ts
context.effects = {
  queue: [] as { path: string; cursor: number }[]
};
```

큐에는 **실행할 이펙트의 위치 정보**만 저장합니다:
- `path`: 어떤 컴포넌트의
- `cursor`: 몇 번째 훅인지

실제 effect 함수와 cleanup은 `hooks[cursor]`에 저장되어 있습니다.

#### 실행 타이밍 비교

```typescript
// 현재 코드 (문제)
withEnqueue(effect);  // effect를 스케줄링하지만 cleanup 저장 안 함

// 올바른 방법
context.effects.queue.push({ path, cursor });  // 위치만 저장
// → flushEffects에서 cleanup 실행 → effect 실행 → 새 cleanup 저장
```

#### 요약

1. **useEffect**: `context.effects.queue.push({ path, cursor })`로 큐에 추가
2. **flushEffects**: 큐에서 꺼내서 cleanup → effect → cleanup 저장
3. **render**: 렌더링 후 `queueMicrotask(flushEffects)` 호출

이렇게 하면 테스트의 `await flushMicrotasks()` 후에 effect가 실행됩니다!
