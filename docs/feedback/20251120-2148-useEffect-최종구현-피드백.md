### useEffect (hooks.ts:65-91)
```typescript
export const useEffect = (effect: () => (() => void) | void, deps?: unknown[]): void => {
  const path = context.hooks.currentPath;
  const hooks = context.hooks.currentHooks;
  const cursor = context.hooks.currentCursor;

  const prevHooks = hooks[cursor] as EffectHook | undefined;
  const prevDeps = prevHooks?.deps;

  const shouldRun = prevDeps === undefined || deps === undefined || !shallowEquals(prevDeps, deps);

  hooks[cursor] = {
    kind: HookTypes.EFFECT,
    deps,
    effect,
    cleanup: prevHooks?.cleanup,
  } as EffectHook;

  if (shouldRun) {
    prevHooks?.cleanup?.();  // 동기적으로 cleanup 실행
    context.effects.queue.push({ path, cursor });
  }
  context.hooks.cursor.set(path, cursor + 1);
};
```

### cleanupUnusedHooks (hooks.ts:10-23)
```typescript
export const cleanupUnusedHooks = () => {
  const hooks = context.hooks.state;
  const cursors = context.hooks.cursor;
  const visited = context.hooks.visited;

  Object.entries(hooks).forEach(([path, hookArray]) => {
    if (visited.has(path)) return;
    hookArray.forEach((hook) => {
      if (hook?.kind === HookTypes.EFFECT && hook.cleanup) hook.cleanup();
    });
    hooks.delete(path);
    cursors.delete(path);
  });
};
```

### flushEffects (render.ts:21-33)
```typescript
enqueue(() => {
  const effects = context.effects.queue;
  context.effects.queue = [];

  effects.forEach(({ path, cursor }) => {
    const hooks = context.hooks.state.get(path);
    if (!hooks) return;
    const hook = hooks[cursor] as EffectHook;
    hook.cleanup?.();  // 여기서 또 cleanup 실행
    const cleanup = hook.effect();
    hook.cleanup = cleanup || null;
  });
});
```

## 피드백

### ✅ 잘한 점

#### 1. useEffect의 기본 구조가 올바릅니다
```typescript
const path = context.hooks.currentPath;
const hooks = context.hooks.currentHooks;
const cursor = context.hooks.currentCursor;
```
훅의 상태를 올바르게 가져오고, 커서를 활용하여 훅의 호출 순서를 추적하는 방식이 정확합니다! React의 훅 시스템 핵심을 잘 이해했습니다.

#### 2. 의존성 비교 로직이 잘 작성되었습니다
```typescript
const shouldRun = prevDeps === undefined || deps === undefined || !shallowEquals(prevDeps, deps);
```
- 첫 렌더링 (prevDeps === undefined) → 실행
- deps 없이 호출 (deps === undefined) → 매번 실행
- 의존성 변경 → 실행

세 가지 케이스를 모두 올바르게 처리했습니다! 👏

#### 3. EffectHook 객체를 저장하는 구조가 적절합니다
```typescript
hooks[cursor] = {
  kind: HookTypes.EFFECT,
  deps,
  effect,
  cleanup: prevHooks?.cleanup,
} as EffectHook;
```
effect 함수와 deps를 함께 저장하여 나중에 사용할 수 있도록 한 점이 좋습니다.

#### 4. reconciler에서 visited 등록을 올바르게 구현했습니다
```typescript
// mount 함수 내 (reconciler.ts:118-119)
context.hooks.componentStack.push(path);
context.hooks.visited.add(path);

// update 함수 내 (reconciler.ts:169-170)
context.hooks.componentStack.push(path);
context.hooks.visited.add(path);
```
컴포넌트가 mount/update될 때 visited에 등록하여 언마운트된 컴포넌트를 식별할 수 있도록 했습니다!

#### 5. flushEffects에서 큐를 올바르게 비웁니다
```typescript
const effects = context.effects.queue;
context.effects.queue = [];
```
먼저 큐를 가져온 후 비우는 방식으로, 효과 실행 중에 추가된 새 효과들이 다음 사이클에 실행되도록 보장합니다.

### 🤔 개선할 점

#### 1. **cleanup이 두 번 실행됩니다** ⚠️ 중요!

**현재 문제:**
```typescript
// useEffect 내부 (hooks.ts:86)
if (shouldRun) {
  prevHooks?.cleanup?.();  // 첫 번째 cleanup 실행 (동기)
  context.effects.queue.push({ path, cursor });
}

// flushEffects 내부 (render.ts:29)
hook.cleanup?.();  // 두 번째 cleanup 실행 (비동기)
const cleanup = hook.effect();
```

**왜 문제인가요?**

의존성이 변경될 때 cleanup이 **두 번** 호출됩니다:
1. useEffect 호출 시 동기적으로 한 번
2. flushEffects에서 effect 실행 전 한 번

테스트 `useEffect 클린업은 재실행과 언마운트 시 호출된다`가 `expected 2 to be 1`로 실패하는 이유입니다.

**해결 방법:**
```typescript
// ❌ 현재: useEffect에서 cleanup 실행
if (shouldRun) {
  prevHooks?.cleanup?.();  // 이 줄 제거!
  context.effects.queue.push({ path, cursor });
}

// ✅ 개선: useEffect에서 cleanup 제거
if (shouldRun) {
  context.effects.queue.push({ path, cursor });
}

// flushEffects에서만 cleanup 실행 (이미 되어있음)
hook.cleanup?.();
const cleanup = hook.effect();
hook.cleanup = cleanup || null;
```

React의 실제 동작에서 cleanup은 **항상 비동기**로 실행됩니다. DOM 업데이트가 완료된 후에 이전 effect의 cleanup → 새 effect 순서로 실행됩니다.

#### 2. **Object.entries(hooks)에서 Map 사용 오류** ⚠️ 중요!

**현재 문제:**
```typescript
export const cleanupUnusedHooks = () => {
  const hooks = context.hooks.state;  // Map 타입
  // ...
  Object.entries(hooks).forEach(([path, hookArray]) => {  // Map에 Object.entries 사용
```

**왜 문제인가요?**

`context.hooks.state`는 `Map<string, HookValue[]>` 타입입니다. `Object.entries()`는 일반 객체에만 동작하고, **Map에는 동작하지 않습니다**!

```typescript
const map = new Map([['a', 1], ['b', 2]]);
Object.entries(map);  // [] - 빈 배열!
```

이로 인해 `cleanupUnusedHooks`가 실제로 아무것도 정리하지 않습니다!

테스트 `언마운트된 컴포넌트의 훅 상태를 정리한다`가 실패하는 핵심 원인입니다.

**해결 방법:**
```typescript
// ❌ 현재: Map에 Object.entries 사용
Object.entries(hooks).forEach(([path, hookArray]) => {

// ✅ 개선: Map.entries() 또는 forEach 사용
hooks.forEach((hookArray, path) => {
  if (visited.has(path)) return;
  hookArray.forEach((hook) => {
    if (hook?.kind === HookTypes.EFFECT && hook.cleanup) hook.cleanup();
  });
  hooks.delete(path);
  cursors.delete(path);
});
```

#### 3. **언마운트 시 cleanup이 실행되지 않습니다** ⚠️ 중요!

**현재 문제:**

`cleanupUnusedHooks`가 Map을 순회하지 못하기 때문에, 컴포넌트가 언마운트될 때 effect의 cleanup 함수가 호출되지 않습니다.

테스트 `effect cleanup 실행 시점 검증`에서:
```typescript
toggle!();  // Child 컴포넌트 언마운트
await flushMicrotasks();
expect(cleanupOrder).toEqual(["cleanup"]);  // 실패! 빈 배열
```

**해결 방법:**

위의 #2 문제를 해결하면 자동으로 해결됩니다. 추가로, cleanup이 실행된 후 훅 상태가 올바르게 삭제되는지도 확인해야 합니다.

#### 4. **동일 참조 객체 deps 비교 문제** 💡 권장

**현재 문제:**

테스트 `동일 참조 객체 deps 비교에서 예상과 다른 동작`이 실패합니다.

```typescript
const sameObj = { count };
useEffect(() => {
  effectRuns.push(count);
}, [sameObj]);  // 매번 새 객체 생성
```

현재 `shallowEquals`가 객체 참조만 비교하므로, 매번 새 객체가 생성되면 effect가 매번 실행되어야 합니다.

**확인 필요:**

`shallowEquals` 함수가 어떻게 구현되어 있는지 확인하세요:
```typescript
// 예상되는 동작
shallowEquals([{a: 1}], [{a: 1}])  // false (다른 참조)
shallowEquals([obj], [obj])         // true (같은 참조)
```

테스트에서 `effectRuns.length > 1`을 기대하는데, 현재는 1입니다. 이는 의존성 비교가 올바르게 동작하지 않을 수 있습니다.

#### 5. **key 재배치 시 DOM 재사용 문제** 📝 참고

**현재 문제:**

테스트 `key가 있는 자식을 재배치할 때 기존 DOM을 재사용한다`가 실패합니다.

이것은 `reconcileChildren` 함수의 문제로, useEffect 구현과는 직접적인 관련이 없습니다. 하지만 key 변경 시 cleanup이 호출되어야 하는 테스트(`key가 변경되면 이전 인스턴스를 언마운트하고 새로 마운트한다`)와 연관됩니다.

### 💡 학습 포인트

#### 1. Effect의 실행 타이밍

```
렌더링 시작
    ↓
컴포넌트 실행 (useEffect 호출, 큐에 추가)
    ↓
DOM 업데이트 (reconcile)
    ↓
마이크로태스크 큐
    ↓
flushEffects 실행
    ↓
이전 cleanup 실행 → 새 effect 실행 → 새 cleanup 저장
```

**핵심**: cleanup은 **항상 비동기**로 실행되어야 합니다. DOM 업데이트 후, 다음 effect 실행 직전에 이전 cleanup을 호출합니다.

#### 2. Map vs Object 순회 방법

```typescript
// Object 순회
const obj = { a: 1, b: 2 };
Object.entries(obj);        // [['a', 1], ['b', 2]]
Object.keys(obj);           // ['a', 'b']
Object.values(obj);         // [1, 2]

// Map 순회
const map = new Map([['a', 1], ['b', 2]]);
map.forEach((value, key) => { });  // ✅
Array.from(map.entries());          // ✅
for (const [key, value] of map) { } // ✅
Object.entries(map);                 // ❌ 빈 배열!
```

#### 3. useEffect Cleanup의 실행 시점

| 상황 | Cleanup 실행 | Effect 실행 |
|------|-------------|-------------|
| 첫 렌더링 | X | O |
| 의존성 변경 | O (이전 것) | O (새 것) |
| 컴포넌트 언마운트 | O | X |
| 의존성 동일 | X | X |
