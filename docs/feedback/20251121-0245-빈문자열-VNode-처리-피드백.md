# 빈 문자열 VNode 처리 피드백

**작성일**: 2025-11-21 02:45
**관련 파일**: `packages/react/src/core/elements.ts`, `packages/react/src/core/reconciler.ts`

---

## 오류 상황

### 발생 위치
`CartModal` 컴포넌트에서 `isOpen`이 `false`일 때 빈 문자열 `""`이 반환됨.

### 오류 흐름
```
CartModal(isOpen: false)
  → return ""
  → reconcile(parentDom, instance, "", path)
  → mount(parentDom, "", path)
  → const { key, props = {}, type } = ""  // 오류 발생!
```

### 핵심 문제
빈 문자열 `""`이 VNode로 처리되지 않고 그대로 `reconcile`까지 전달되어, `mount` 함수에서 destructuring 시 오류 발생.

---

## 제안된 해결 방법

### 방법 1: mount 함수에서 방어 코드 추가

```typescript
const mount = (parentDom: HTMLElement, node: VNode, path: string) => {
  if (!node || typeof node !== "object") return null;
  // ...
};
```

**장점**:
- 빠르게 오류를 방지할 수 있음
- 다른 예상치 못한 케이스도 처리 가능

**단점**:
- 근본적인 해결이 아님
- 잘못된 값이 여기까지 도달한 것 자체가 문제
- 타입 안정성 저하 (VNode가 아닌 값을 허용)

---

### 방법 2: normalizeNode에서 빈 문자열 처리

현재 `normalizeNode`는 `createElement`의 children을 정규화할 때만 사용됨.
컴포넌트가 반환하는 값에는 적용되지 않음.

**해결 방향**: 컴포넌트 반환값도 정규화하기

```typescript
// reconciler.ts의 mount 함수 - component 케이스
if (typeof type === "function") {
  context.hooks.componentStack.push(path);
  context.hooks.visited.add(path);
  const rawVNode = type(props);
  const newVNode = normalizeNode(rawVNode);  // 정규화 추가
  context.hooks.componentStack.pop();

  const childInstance = reconcile(parentDom, null, newVNode, path);
  // ...
}
```

**장점**:
- 근본적인 해결
- 컴포넌트가 문자열, 숫자, null, undefined, boolean 등을 반환해도 처리 가능
- React의 실제 동작과 일치

**단점**:
- 여러 곳에 적용해야 함 (mount의 component, update의 component)

---

### 방법 3: reconcile 진입점에서 정규화

```typescript
export const reconcile = (
  parentDom: HTMLElement,
  instance: Instance | null,
  node: VNode | null,
  path: string,
): Instance | null => {
  // 진입 시 정규화
  const normalizedNode = typeof node === "object" ? node : normalizeNode(node as any);

  if (normalizedNode === null) {
    return unmount(parentDom, instance);
  }
  // ...
};
```

**장점**:
- 한 곳에서 모든 케이스 처리
- 가장 안전한 방법

**단점**:
- 타입 정의가 복잡해질 수 있음
- 매 reconcile 호출마다 체크가 발생 (성능)

---

## 권장 해결 방법

**방법 2 (normalizeNode 활용)**를 권장합니다.

### 이유

1. **React의 실제 동작과 일치**
   - React에서 컴포넌트는 `null`, 문자열, 숫자 등을 반환할 수 있음
   - 이를 내부적으로 정규화하여 처리

2. **관심사 분리**
   - 정규화는 `normalizeNode`의 책임
   - `reconcile`/`mount`는 정규화된 VNode만 처리

3. **일관성**
   - `createElement`의 children도 `normalizeNode`로 처리
   - 컴포넌트 반환값도 동일하게 처리

### 구현 위치

1. **mount 함수의 component 케이스** (줄 120-123)
2. **update 함수의 component 케이스** (줄 168-171)

```typescript
// mount - component
if (typeof type === "function") {
  context.hooks.componentStack.push(path);
  context.hooks.visited.add(path);
  const rawVNode = type(props);
  const newVNode = normalizeNode(rawVNode);  // 추가
  context.hooks.componentStack.pop();

  const childInstance = reconcile(parentDom, null, newVNode, path);
  // ...
}

// update - component
case "component": {
  context.hooks.componentStack.push(path);
  context.hooks.visited.add(path);
  const rawVNode = (node.type as (props: unknown) => VNode)(node.props || {});
  const newVNode = normalizeNode(rawVNode);  // 추가
  context.hooks.componentStack.pop();
  // ...
}
```

## 추가 고려사항

### isEmptyValue 수정 필요 여부

현재 `isEmptyValue`는 빈 문자열을 empty로 처리함:

```typescript
export const isEmptyValue = (value: unknown): boolean => {
  if (typeof value === "number") return false;
  return !value;  // "" → true
};
```

이건 올바른 동작임. 빈 문자열은 렌더링할 내용이 없으므로 `null`로 처리되어야 함.

### normalizeNode의 타입 확장

컴포넌트 반환값을 처리하려면 타입을 확장해야 할 수 있음:

```typescript
export const normalizeNode = (
  node: VNode | string | number | null | undefined | boolean
): VNode | null => {
  // ...
};
```

## 테스트 케이스

수정 후 확인해야 할 케이스:

1. 컴포넌트가 `""` 반환 → 아무것도 렌더링되지 않음
2. 컴포넌트가 `null` 반환 → 아무것도 렌더링되지 않음

4. 컴포넌트가 `"text"` 반환 → 텍스트 노드 렌더링
5. 컴포넌트가 `123` 반환 → 텍스트 노드 렌더링

## 최종 해결책

### 적용한 방법

`mount` 함수 최하단의 `throw Error`를 `return null`로 변경:

```typescript
const mount = (parentDom: HTMLElement, node: VNode, path: string) => {
  // ... 기존 코드 ...

  // 기존: throw new Error(`알 수 없는 노드 타입: ${String(node.type)}`);
  return null;  // 변경
};
```

### 이 방법의 장점

1. **간단함**: 한 줄로 해결
2. **안전함**: 예상치 못한 타입이 들어와도 크래시 없이 처리
3. **방어적**: 빈 문자열, 잘못된 타입 등 다양한 엣지 케이스 처리

### 이 방법의 단점

1. **조용한 실패**: 잘못된 값이 들어와도 에러 없이 무시됨
   - 디버깅 시 문제 원인을 찾기 어려울 수 있음

2. **근본 원인 숨김**: 빈 문자열이 여기까지 온 것 자체가 비정상인데, 그걸 무시하고 넘어감

### 개선 제안 (선택사항)

개발 환경에서는 경고를 출력하여 디버깅을 용이하게 할 수 있음:

```typescript
if (process.env.NODE_ENV === 'development') {
  console.warn(`Invalid node type passed to mount: ${typeof node}`, node);
}
return null;
```

### 결론

**실용적인 해결책**입니다. 실제 React도 내부적으로 비슷하게 처리합니다. 완벽한 해결책보다 **동작하는 코드**가 우선이며, 나중에 더 근본적인 해결이 필요하다면 방법 2를 적용할 수 있습니다.
