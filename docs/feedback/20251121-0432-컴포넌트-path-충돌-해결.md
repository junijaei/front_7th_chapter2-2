# 컴포넌트 Path 충돌로 인한 Hook State 공유 문제 해결

**작성일**: 2025-11-21 04:32
**관련 파일**: `packages/react/src/core/reconciler.ts`

---

## 문제 상황

### 에러 메시지
```
useMemo.ts:20 Uncaught TypeError: Cannot read properties of undefined (reading 'value')
    at useMemo (useMemo.ts:20:20)
    at PageWrapper (PageWrapper.jsx:15:21)
    at mount (reconciler.ts:100:22)
    at mount (reconciler.ts:105:40)
```

### 증상
`PageWrapper`의 `useMemo` 내부에서 `useRef`를 호출할 때, `useState`가 반환한 값이 예상과 다름:

```javascript
// useRef.ts에서 console.log(state) 출력
{kind: 'effect', deps: Array(0), effect: ƒ, cleanup: ƒ}
```

**예상값**: `{ current: ... }` (useState가 저장한 ref 객체)
**실제값**: effect hook 객체

---

## 원인 분석 과정

### 1단계: 에러 스택 분석

```
at mount (reconciler.ts:100:22)   // type(props) 호출
at mount (reconciler.ts:105:40)   // 자식 mount
```

`mount`가 두 번 호출되고 있음. 줄 번호를 확인:
- 100번: `const rawVNode = type(props);` - 컴포넌트 함수 실행
- 105번: `mount(parentDom, childVNode, path)` - 자식 VNode mount

### 2단계: Hook Cursor 문제 추론

`useRef`가 반환한 값이 effect hook이라는 것은 **cursor가 잘못된 위치**를 가리키고 있다는 의미.

```javascript
// hooks 배열 상태 (예상)
hooks[0] = { current: ... }  // useState from useRef
hooks[1] = ...               // 다른 hook

// hooks 배열 상태 (실제)
hooks[0] = { kind: 'effect', ... }  // useEffect!
```

### 3단계: Path 시스템 이해

React의 hook 시스템은 **path**를 키로 사용하여 각 컴포넌트의 hook state를 저장:

```typescript
context.hooks.state = Map<path, hookArray[]>
```

같은 path를 사용하면 같은 hook 배열을 공유하게 됨.

### 4단계: 컴포넌트 구조 분석

```jsx
// App.jsx
export function App() {
  const forceUpdate = useForceUpdate();  // useState (cursor 0)
  useEffect(() => { ... }, []);          // useEffect (cursor 1)
  return <PageComponent />;              // HomePage
}
```

App의 hooks:
- cursor 0: useState (from useForceUpdate)
- cursor 1: useEffect

### 5단계: 문제 코드 발견

```typescript
// reconciler.ts - mount 함수의 함수형 컴포넌트 처리
if (typeof type === "function") {
  context.hooks.componentStack.push(path);
  context.hooks.visited.add(path);
  const rawVNode = type(props);  // App 실행, hooks 사용
  context.hooks.componentStack.pop();

  // 자식 mount - 같은 path 사용!
  const childInstance = childVNode ? mount(parentDom, childVNode, path) : null;
}
```

**문제 발견**: 자식 VNode를 mount할 때 **부모와 같은 path**를 사용!

### 6단계: 실제 동작 시나리오

```
1. App mount (path: "")
   - useState 호출 → hooks[""][0] = useState 값
   - useEffect 호출 → hooks[""][1] = useEffect 객체

2. App이 반환한 <PageComponent /> mount (path: "" - 같은 path!)
   - HomePage가 실행될 때 hooks[""]를 사용

3. HomePage → PageWrapper mount (path: "" - 같은 path!)
   - PageWrapper의 useMemo가 hooks[""][0]을 읽음
   - 하지만 이미 App의 useState가 저장되어 있음
   - cursor가 증가하면서 hooks[""][1]을 읽음 → useEffect 객체!
```

### 7단계: 근본 원인 확인

**원인**: 컴포넌트가 반환하는 자식 VNode를 mount할 때 부모와 같은 path를 사용하여 hook state가 공유됨.

원래 의도는 "컴포넌트의 자식은 컴포넌트의 일부"라고 생각했지만, 자식이 **또 다른 컴포넌트**인 경우 별도의 hook state가 필요함.

## 수정 후 Path 구조

```
App (path: "")
  └─ HomePage (path: ".cHomePage_0")
       └─ PageWrapper (path: ".cHomePage_0.cPageWrapper_0")
            └─ div (path: ".cHomePage_0.cPageWrapper_0.i0")
```

각 컴포넌트가 고유한 path를 가지므로 hook state가 분리됨.

## 학습 포인트

### 1. Path 시스템의 중요성

React의 hook 시스템은 **컴포넌트 인스턴스 식별**을 위해 path를 사용함:
- 같은 path = 같은 hook state 공유
- 다른 path = 별도의 hook state

### 2. 컴포넌트 vs 자식 VNode

```jsx
function Parent() {
  return <Child />;  // Child는 Parent의 "자식"이 아닌 별도의 컴포넌트
}
```

컴포넌트가 반환하는 VNode가:
- **host 요소** (div, span 등): hooks를 사용하지 않으므로 같은 path 가능
- **다른 컴포넌트**: 별도의 hooks를 사용하므로 고유한 path 필요

### 3. 에러 디버깅 방법

1. **에러 스택 분석**: 어디서 호출되었는지 추적
2. **데이터 타입 확인**: 예상 타입과 실제 타입 비교
3. **시스템 이해**: path, cursor 등 내부 동작 원리 파악
4. **시나리오 재현**: 실제 실행 흐름 따라가기

### 4. createChildPath 함수의 역할

```typescript
createChildPath(parentPath, key, index, nodeType, siblings?)
```

- key가 있으면: `${parentPath}.k${key}`
- 컴포넌트면: `${parentPath}.c${ComponentName}_${sameTypeIndex}`
- 일반 요소면: `${parentPath}.i${index}`

이를 통해 각 노드에 고유한 식별자를 부여.

## 관련 코드 흐름

### Hook 사용 시

```typescript
// hooks.ts - useState
export const useState = <T>(initialValue: T | (() => T)) => {
  const path = context.hooks.currentPath;      // 현재 컴포넌트 path
  const hooks = context.hooks.currentHooks;    // path에 해당하는 hook 배열
  const cursor = context.hooks.currentCursor;  // 현재 hook 인덱스

  if (hooks[cursor] === undefined) {
    hooks[cursor] = /* 초기값 */;
  }

  context.hooks.cursor.set(path, cursor + 1);  // cursor 증가
  return [hooks[cursor], setState];
};
```

### 컴포넌트 실행 시

```typescript
// reconciler.ts - mount
context.hooks.componentStack.push(path);  // path 설정
const rawVNode = type(props);              // 컴포넌트 실행 (hooks 호출)
context.hooks.componentStack.pop();        // path 복원
```

| 구분 | Before | After |

| 자식 path | 부모와 동일 (`path`) | 고유한 path (`childPath`) |
| Hook state | 부모-자식 공유 | 각각 분리 |
